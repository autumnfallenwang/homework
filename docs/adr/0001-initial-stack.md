# 0001 — Initial tech stack

- **Status:** accepted
- **Date:** 2026-05-30
- **Deciders:** project founder (captured during `/devkit-init`)

## Context

This is the founding stack decision for the project, recorded at scaffold time. It captures what we picked and why, so future contributors can understand the constraints in play when these choices were made.

homework begins as a migration of the TeacherEase Parent Companion desktop app to the home k3s cluster. Two sibling projects — `homenews` and `homecal` — already run on this cluster and have converged on a common stack and deployment model. Choosing the same stack keeps the three projects operationally consistent and lets homework reuse the established `arch-infra` GitOps pipeline rather than inventing a new one.

## Decision

- **Primary language:** typescript
- **Package manager:** pnpm
- **Monorepo:** Turborepo + pnpm
- **Backend:** Hono + Zod (`apps/api`)
- **Frontend:** Next.js App Router (`apps/web`)
- **Database:** PostgreSQL + Drizzle
- **Shared:** Zod schemas + types (`packages/shared`)
- **Test:** Vitest
- **Lint / format:** Biome
- **Typecheck:** tsc (`pnpm tsc --noEmit`)
- **Deploy:** k3s + Argo CD via `arch-infra`, GHCR images, Helm chart at `deploy/chart`

This mirrors `homenews` and `homecal` exactly.

## Consequences

**Positive:** operational and cognitive consistency across the three home apps; reuse of the `arch-infra` pipeline, Loki/Grafana observability, and existing dev patterns; a single language (TypeScript) end to end.

**Trade-offs:** the desktop app's Rust scraping / scheduler / SMTP code must be rewritten in TypeScript rather than ported directly; SQLite's local-first storage is replaced by a server-side PostgreSQL database, which changes how portal credentials and secrets are handled (moving from the OS keychain to in-cluster secrets). The Tauri desktop distribution is retired.

**Open risks:** secret storage in-cluster and the credentials/config schema are not yet settled (see `docs/architecture.md` → Open questions).
